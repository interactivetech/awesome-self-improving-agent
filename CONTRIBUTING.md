# Contributing

Thanks for helping keep this list accurate.

## Add a project

Open a pull request that updates `data/projects.yml` and the README table.

Please include:
- project/method name,
- paper or project page,
- public code repository,
- the persistent component that improves,
- a one-sentence mechanism,
- release status (`official`, `reference`, `third-party`, or `official-borderline`),
- evidence that connects the codebase to the method.

## Add a watchlist item

If a promising self-improvement method has no verified implementation, add it to `data/watchlist.yml` instead of guessing at a code link.

## Quality bar

We prefer:
- author-linked code,
- runnable repositories,
- clear licenses,
- reproducible examples,
- concise descriptions,
- explicit distinction between self-correction and persistent self-improvement.

Please avoid star-count rankings or subjective “best” labels.

## Paper metadata

For research-backed entries, also update `data/papers.yml` with:
- canonical paper title,
- paper URL,
- venue and year when verified,
- corresponding code repository if any,
- code status,
- the persistent surface the method improves.

If a paper has no verified code yet, it still belongs in the paper registry with `code_status: paper-only` and should remain on the watchlist.
